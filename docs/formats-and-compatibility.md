# Archive Format Versioning & Backward Compatibility

`v4zip` maintains strict **bit-exact lossless restoration** (verified via CRC32 and SHA-256) across all modern archive format versions.

## Format Compatibility Matrix

| Archive Format | Written By | Read By Current `v4zip` | DNA Stream Codec |
|---:|---|:---:|---|
| **Format 1** | Rewrite v1.x | Yes | `Predictor` (v1) |
| **Format 2** | `v4zip 2.1.0` | Yes | `PredictorV2` |
| **Format 3** | `v4zip 3.0.0` | Yes | `PredictorV3Legacy` (34 experts) + `RepeatDnaCodec` (legacy v3 header) |
| **Format 4** | **`v4zip 3.1.0`** *(current)* | Yes | `PredictorV3` (37 experts + `rc8/9/10` + 4-way `k=13` match) + `RepeatDnaCodec` (4-way + CRISPR/Palindrome Hotspot Index Table) |

> Legacy archives created by the original upstream `v4zip 1.x` executable (different magic header) still require the original tool.

## Backward Compatibility Guarantee

Because arithmetic range coding is stateful and requires bit-exact CDFs at every base, `v3.1` bumps the emitted archive format from `3` to `4` in [`src/archive2.cpp`](../src/archive2.cpp) and preserves the exact `v3.0.0` 34-expert predictor in [`src/detail/predictor_v3_legacy.hpp`](../src/detail/predictor_v3_legacy.hpp).

Every archive generated by `v2.1.0` (Format 2) and `v3.0.0` (Format 3) decompresses bit-for-bit identically with the `v3.1` binary.

## Decoder Safety & Hardening

To defend against malformed or adversarial archives:

1. **Output Bound (`--max-output`)**: Decompression refuses archives whose declared original size exceeds `--max-output` (default `1 GiB`).
2. **Dictionary Cap**: `RepeatDnaCodec::decode` rejects `dict_size > 64` before allocation and rejects any word `> 0xFFFFFFFF`.
3. **Token Expansion Cap**: `tok_raw_size` is bounded by `expected_dna * 2 + 64` prior to Zstd decompression to prevent memory-exhaustion bombs.
4. **Atomic Non-Overwriting Output**: Outputs are written to an exclusive temporary file (`O_CREAT | O_EXCL | O_NOFOLLOW`), synced (`fsync`), and published atomically via `linkat` so existing files are never overwritten.
5. **Manifest Path Safety**: `.v4zm` manifests reject part filenames containing `/`, `\`, `.`, or `..`, cap part counts at `10,000`, and verify per-part and global CRC32 checksums.
